# 晶圆缺陷点阵复检审计台

晶圆复检设备会因装片方向与视野偏移，把同一批缺陷记录成**旋转、镜像且平移**后的
二值点阵。抽样叠图或浮点配准可能在八种对称姿态之间选错。本项目从空仓库实现一个
全栈审计台：React 页面通过真实 **Gin API** 提交参考图与复检图，遍历正方形的
**八种旋转/镜像姿态**与横纵各 `-(N-1) … (N-1)` 的**整数平移**，用**精确整数
二维相关**求出最大重合缺陷数，按固定规范顺序裁决唯一规范解，并给出红蓝叠加证据。

## 规范与算法

- **输入**：两幅边长 `N ∈ [16,512]` 的二值方阵，仅含 `0`/`1` 与换行，每行等宽。
- **八种姿态（固定裁决顺序）**：
  `identity, rot90, rot180, rot270, mirrorH, mirrorHrot90, mirrorHrot180, mirrorHrot270`
  （rot 为顺时针，mirrorH 为上下翻转）。
- **平移范围**：纵移 `dy`、横移 `dx` 均取 `-(N-1) … N-1`，共 `(2N-1)²` 个；
  每个姿态全部遍历，搜索空间为 `8·(2N-1)²` 个（姿态, 纵移, 横移）三元组。
- **精确二维相关**：重合数即两个 0/1 矩阵的互相关。后端**手写数论变换（NTT，
  模数 998244353，原根 3）**，以「逐行一维 NTT + 逐列一维 NTT」在
  `O(N² log N)` 内一次给出一个姿态的**全部**平移重合值；参考图二维频谱只计算
  一次并在八姿态间复用。由于任一位置重合数 `≤ N² ≤ 262144 < 998244353`，
  模运算结果与真实整数**恒等**，没有任何浮点误差。**禁止也未使用任何现成配准或
  二维相关接口**（无 FFT 库、无图像库、无 scipy/numpy 类依赖）。
- **规范解裁决**：全局最大重合数下，按 **姿态顺序 → 纵移升序 → 横移升序** 取
  第一个三元组；与全局最大值相等的三元组总数即**并列最优数量**（全空输入时
  并列数恰为 `8·(2N-1)²`）。
- **移出画布**：平移后越界的复检缺陷**不参与画布内重合**，但仍计入**复检图原图
  缺陷总数**，并单独统计规范解下移出画布的数量。
- **异常语义**：非法尺寸、字符、行宽均以 422 返回并**定位到具体输入框**（含
  字段、行、列）；两处同时非法会同时报告。服务无状态，任何计算异常都不会留下旧
  结论（前端在收到非成功响应时清空结果区），修正后可原样重试。

## 目录结构

```
backend/    Gin 服务 + 手写 NTT 精确整数二维相关（含 Go 单元测试/暴力交叉核对）
  cmd/server/main.go          HTTP 层（/healthz、/api/meta、/api/audit）
  internal/audit/pose.go      八种规范姿态
  internal/audit/ntt.go       NTT、二维 NTT、互相关
  internal/audit/solve.go     解析校验、遍历、裁决、叠加证据
frontend/   React + Vite 页面，nginx 反代 /api 与 /healthz
verify/     Compose 中名为 verify 的服务：独立 O(N⁴) 暴力实现交叉核对真实 API
docker-compose.yml
```

## 运行（Docker Compose）

```bash
# 构建并常驻运行前后端
docker compose up --build

# 浏览器打开（端口可用环境变量覆盖）
#   http://localhost:8088
```

可配置宿主机端口（见 `.env.example`）：

```bash
FRONTEND_PORT=8000 BACKEND_PORT=9090 docker compose up --build
```

### 可观察验收

`verify` 服务对**真实运行中的 backend** 执行端到端核对，逐条打印 PASS/FAIL 并以
退出码给出结论：

```bash
docker compose up --build verify
# 或：docker compose run --build verify
# 或：docker compose logs verify
```

验收内容（69 项断言）包括：

- 健康检查与固定姿态顺序；
- 多组 `N=16…48`、不同密度随机点阵：最大重合、并列数、规范姿态/纵移/横移、
  原图缺陷总数、移出画布数、红蓝叠加逐格、搜索空间规模，全部与**独立重写的
  O(N⁴) 暴力遍历**一致；
- 已知变换（rot180 + 平移 `(3,-5)`）被规范解唯一还原；
- 越界缺陷仍计入原图总数；
- **512×512 稠密满尺寸**在秒级完成（证明不是逐点尝试全部平移）；
- 非法字符（定位到字段/行/列）、行宽不一致、边长越界、非方阵、两图边长不一致、
  两处同时非法；
- 合法→非法→修正后原样重试，结论不串不留。

后端自带单元测试（含与暴力实现的随机对照、512 稠密/全空性能与并列数）：

```bash
cd backend && go test ./...
```

## HTTP 接口

- `GET /healthz` → `200 {"status":"ok",...}`
- `GET /api/meta` → 边长范围与固定姿态顺序
- `POST /api/audit`
  ```json
  { "reference": "0101\n...\n", "recheck": "0101\n...\n" }
  ```
  成功 `200` 返回：规范变换（姿态名/索引、dy、dx）、最大重合数、并列最优数、
  两图原图缺陷总数、移出画布数、八姿态各自最优、红蓝叠加矩阵（`.`/`R`/`B`/`X`）
  与遍历空间规模；校验失败 `422` 返回定位到 `reference`/`recheck` 的错误数组；
  请求体上限 4MiB。
